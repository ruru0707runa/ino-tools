# Extract Course Know-How

## Measure the material before you promise a full run

- Count the lessons, videos, guides and pages before you estimate time or completeness.

- Open one small prototype sample and agree the output format with the user before you run the full extraction.

- Offer tiered time options when the full run is long, and state what each tier covers and what it leaves out.

- Re-estimate in the open when an early estimate proves wrong, and name the corrected figure rather than defending the first one.

## Extract procedures, not wording

- Rewrite each procedure in your own words, and keep only the steps, settings, prompts and use cases another agent needs.

- Stop verbatim subtitle or text extraction when the source blocks it on rights grounds, and switch to know-how extraction without seeking a workaround.

- Label every instructor claim as a claim, and keep it separate from facts you verified in the source.

- Follow a standing safety or no-efficacy rule when it conflicts with a course claim, and note the conflict plainly.

## Keep gaps visible instead of filling them

- List every item you could not open, play or verify, with the reason it stayed unconfirmed.

- Leave a gap blank in the output when the source does not supply it, and never invent a price, limit, plan name, amount or proper noun to complete a list.

- Check for duplicate files and duplicate lessons before you count the material, and report duplicates as duplicates rather than counting them twice.

- Reconcile every count before delivery, so category totals and item lists add up to the stated total.

- Reopen the source when the user challenges completeness, and correct the output rather than arguing from memory.

## Present a transfer-ready set

- Separate methods that work for any agent from steps that belong to one product or one account.

- Organize the set into a short summary, a know-how section, a practical output section and a claims and unconfirmed section.

- Name the source files and the scope of each section, so a later agent can check what came from where.

- Ask the user to supply source files directly when browser access cannot download or play the material, and proceed only with what the user supplies.

## Available connectors

- Use `muse.connector_search` to find other connectors and `muse.skill_search` to find related skills.

- If nothing here fits, look on the web for a maintained API or MCP server and set it up with [Custom Connectors and MCPs](/opt/muse/skills/custom-connector-setup/SKILL.md), or build a custom connector.

## Alternatives for better results

- Start with the smallest useful extraction when the full set is large, and expand it only after the user approves the prototype.

- Split a very large set into a summary pass and a detail pass, so an unplayable or blocked item does not stall the whole job.

- Return the unconfirmed list alongside the finished set, so the user can decide whether to supply the missing source.
